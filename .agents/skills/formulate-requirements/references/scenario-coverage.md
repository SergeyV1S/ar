# Проверка охвата сценариев

Для каждого существенного пользовательского и системного сценария пройди проверку ниже. Используй описание процесса, вариант использования, схему или контракт как материал для извлечения обязательств.

1. Определи инициатора, событие запуска, предусловия, начальное состояние и права доступа. Зафиксируй входные данные, обязательные поля, правила проверки и значимые границы.
2. Пройди основной успешный поток до результата. Выдели ответы системы, выдаваемые данные и изменения состояния в границах продукта.
3. Проверь применимые альтернативы и исключения. Рассмотри ошибки пользователя, некорректные или неполные данные, недостаточные права, повтор операции и уже изменённое состояние. Проверь недоступность сети, хранилища, внешнего сервиса или другого компонента, от которого зависит исход. Выбирай ветви по источникам и последствиям для функции, данных или возможности продолжить работу.
4. Для каждой существенной ветви найди условие её начала, реакцию и получателя ответа, последствия для сохранённых и обрабатываемых данных, итоговое состояние и возможность продолжить, возобновить или повторить действие. При необходимости различай сбой до сохранения, во время него и после сохранения до получения ответа.
5. Сформулируй известное поведение и проверяемые критерии. Для полного сценария хватит связанных критериев одного ФТ, если ветки проверяют одно обязательство. Для самостоятельных результатов выделяй отдельные ФТ. Для значимых неизвестных ветвей используй [разбор пробелов](clarify-gaps.md).

При чтении спецификации варианта использования сверь постусловия с шагами, бизнес-правилами, сроками и связанными функциями. При противоречии уточни целевое поведение.
