# Критерии приёмки

Критерий отвечает, какое наблюдение подтверждает выполнение требования. Сверь набор критериев с формулировкой, чтобы условия проверки сохраняли её смысл и каждое ожидаемое поведение было задано.

- **Дано → Когда → Тогда.** Зафиксируй существенное начальное состояние, событие или действие и результат. Этот формат подходит для перехода состояния и проверки действий пользователя.
- **Таблица правил.** Столбцы содержат влияющие условия и ожидаемый исход. Если варианты различаются на пороге, проверь его включение и ветвь за порогом. Сочетание, отсутствующее в исходнике, требует уточнения, если оно влияет на охват.
- **Краткая проверка или чек-лист.** Подходит для конкретного набора полей одного результата либо однозначной проверки соответствия. Независимые действия даже в одном чек-листе могут относиться к разным ФТ или НФТ.

В сценариях с общими предусловиями их можно указать один раз для всей группы. Если правило для нескольких входов одинаково, используй один сценарий с параметрами и таблицу входов и ожидаемых результатов. Для отличающихся исходов опиши позитивную, негативную или граничную проверку по применимости. Если сценарий описывает ошибку, проверь сообщение или состояние после ошибки в той мере, в какой они определены.

Для БТ результатом проверки служит измеренный бизнес-эффект. Для количественного НФТ сопоставь измерение с порогом при оговорённых условиях. Условия приёмки относятся к конкретной функции или свойству и проверяются при приёмке. Definition of Done применяется ко всем задачам команды и может включать ревью, обновление документации и прохождение тестов.
