# Категории нефункциональных требований

Для НФТ задай свойство системы или обязательное ограничение и область его действия. Для метрики зафиксируй порог или диапазон, единицу и существенные условия измерения. Для ограничения укажи объект и способ однозначно установить соответствие.

При анализе НФТ обязательно оцени [отказоустойчивость](availability-recovery.md) и [масштабируемость](capacity-scalability.md) по отдельности, даже если материалы не называют эти свойства. Для каждого свойства укажи фрагмент, сценарий или риск, из которого следует применимость, либо причину, по которой обсуждение сейчас не нужно. Приоритет и глубину определяй по последствиям для кейса, ограничениям и объёму MVP.

| Свойство и основание для проверки | Что уточнить |
|---|---|
| Производительность. Значима скорость операции | Операция, задержка, перцентиль, объём запросов и данных |
| Масштабируемость. Ожидается рост нагрузки или данных | Текущий и целевой профиль нагрузки, горизонт роста, сохраняемые свойства на целевой нагрузке |
| Отказоустойчивость. Сбой влияет на работу или данные | Сценарий отказа, допустимое прерывание, целостность данных, восстановление, допустимые время восстановления и потеря данных |
| Данные или операции требуют защиты | Объект защиты, область доступа, контролируемое действие или обязательный уровень защиты |
| Пользователь должен легко выполнить задачу | Роль, задача, условия, наблюдаемый результат и показатель удобства или доступности |
| Система должна работать в заданной среде | Поддерживаемые версии, платформы и применимые операции |
| Система подчиняется нормам или хранит данные заданный срок | Источник обязательства, применимый пункт, вид данных, срок и условия отсчёта |
| Продукт должен легко изменяться | Конкретное изменение, результат и условия оценки |

Для каждого потенциально нужного НФТ приведи основание и статус по [правилам трассировки](traceability.md). При достаточных данных сформулируй измеримый критерий. Если исходных значений нет, укажи параметры для согласования и задай конкретные вопросы по операциям и последствиям. Общие слова о стабильности и масштабируемости служат сигналом для уточнения. Порог, обязательные условия проверки и технологическое ограничение должны иметь источник в проекте.
