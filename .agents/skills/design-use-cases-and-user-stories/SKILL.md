# Проектирование Use Case и User Story

## Порядок работы

1. Прочитай входные требования. Выдели бизнес-цели, границы, роли и внешних участников, пользовательские задачи, правила и ограничения. Сохрани имеющиеся идентификаторы и ссылки на источник. Используй [уровни требований и трассировку](references/requirements-traceability.md).
2. До детализации проверь, какие решения о поведении уже заданы. При пробеле или противоречии, влияющем на цель, границы, права, ветвление, результат или приёмку, задай пользователю вопрос в диалоге по [порядку уточнения требований](references/interactive-clarification.md). Продолжай работу по согласованной части.
3. Подготовь запрошенный формат. Когда нужны оба, сначала опиши взаимодействия и исходы в Use Case, затем оформи User Stories вокруг отдельных пользовательских ценностей. Свяжи артефакты по смыслу и идентификаторам. Один Use Case может покрывать несколько историй, если у каждой своя ценность.
4. Проверь каждый артефакт по указанным ниже материалам. Сверь роли, термины, начальные состояния, исходы, пороги и бизнес-правила между источником, потоками и критериями. Покажи открытые вопросы рядом с затронутыми сценариями или историями.

## Use Case

- Возьми структуру и правила именования из [спецификации Use Case](references/use-case-specification.md). Для различения успешного пути, альтернатив, ошибок и их исходов прочитай [описание потоков](references/use-case-flows.md).
- Сверь полноту и размещение деталей по [спецификации подтверждения алерта](examples/use-case-alert-acknowledgement.md). Используй вопросы после примера при валидации.
- Для диаграммы или отношений между сценариями прочитай [границы и отношения Use Case](references/use-case-relationships.md) и [Mermaid-диаграмму NMS](examples/use-case-diagram-nms.md). Согласуй диаграмму с текстовой спецификацией.

## User Story и критерии приёмки

- Оформи историю по [формату User Story](references/user-story-format.md) и проверь по [INVEST](references/invest.md). Сверь формулировки с примерами [просмотра алертов](examples/story-view-alerts.md), [подтверждения алерта](examples/story-acknowledge-alert.md) или [экспорта отчёта](examples/story-export-availability.md) по характеру задачи.
- Выбери форму критериев и покрытие по [руководству по приёмке](references/acceptance-coverage.md). Используй подходящую пару справки и примера.

| Задача | Правила | Пример для написания и проверки |
|---|---|---|
| Взаимодействие, событие, переход состояния или негативная ветка | [Gherkin](references/gherkin.md) | [Генерация и обработка алертов](examples/gherkin-alert-lifecycle.md) или [аутентификация](examples/gherkin-authentication.md) |
| Выход зависит от комбинации условий | [Таблица решений](references/decision-tables.md) | [Приоритет алерта](examples/decision-table-alert-priority.md) |
| Небольшая история с простыми проверяемыми результатами | [Чек-лист](references/acceptance-checklists.md) | [Экспорт отчёта](examples/checklist-report-export.md) |

- Если нужен командный Definition of Done, используй [правила применения DoD](references/definition-of-done.md) и [пример команды NMS](examples/definition-of-done-nms.md).

## Проверка результата

- Пройди [чек-лист качества требований](references/requirements-quality.md) и сопоставь сомнительные формулировки с [примерами уточнения требований](examples/requirement-quality.md) и [нарушениями INVEST](examples/invest-violations.md).
- Для Use Case проверь цель актора, причинно-следственный порядок, привязку ветвей к шагам и исход каждой ветви. Для User Story проверь роль, действие, ценность и возможность проверить критерии. Если подготовлены оба формата, проследи ключевые сценарии от источника через Use Case и User Story к критериям.
- Используй примеры как образцы формы и предмет разбора. Роли, числовые значения, статусы и системные действия бери из требований текущего проекта или из ответов пользователя.
