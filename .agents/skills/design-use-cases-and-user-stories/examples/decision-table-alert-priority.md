# Таблица решений для приоритета алерта

Пример из `wiegers_sa_reference.md`, § 5.3, формат 2, US-005 (строки 657–668).

User Story US-005: Расчёт приоритета алерта

| Серьёзность | Тип устройства   | Затронутые клиенты | Приоритет обработки |
|-------------|------------------|--------------------|---------------------|
| CRITICAL    | Core Router      | > 100              | P1 (≤ 5 мин)        |
| CRITICAL    | Core Router      | ≤ 100              | P1 (≤ 5 мин)        |
| CRITICAL    | Access Switch    | > 50               | P1 (≤ 5 мин)        |
| CRITICAL    | Access Switch    | ≤ 50               | P2 (≤ 15 мин)       |
| MAJOR       | Любой            | > 100              | P2 (≤ 15 мин)       |
| MAJOR       | Любой            | ≤ 100              | P3 (≤ 60 мин)       |
| MINOR       | Любой            | Любое              | P4 (≤ 4 часов)      |
| WARNING     | Любой            | Любое              | P5 (в рабочее время)|

## Проверка по примеру

- Проверь границы 50 и 100 клиентов с обеих сторон. Для MAJOR значения на границе и выше дают разные приоритеты.
- Если допустимы другие типы устройств для CRITICAL или другие уровни серьёзности, запроси правило для таких входов. Уточни календарь, если «в рабочее время» влияет на тест.
