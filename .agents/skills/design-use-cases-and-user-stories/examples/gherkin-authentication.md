# Gherkin для входа, блокировки и сброса пароля

Пример из `wiegers_sa_reference.md`, § 5.3, формат 1, аутентификация (строки 622–647).

```gherkin
Feature: Аутентификация пользователя
  Пользователи должны безопасно входить в систему NMS.

  Scenario: Успешная аутентификация через LDAP
    Given пользователь "john.doe@company.com" существует в LDAP
    And аккаунт не заблокирован
    When пользователь вводит корректный логин и пароль
    And нажимает кнопку "Войти"
    Then пользователь перенаправляется на главный дашборд NMS
    And в системе создаётся сессия длительностью 8 часов
    And в лог аудита записывается событие успешного входа

  Scenario: Блокировка после 5 неудачных попыток
    Given пользователь "john.doe@company.com" существует в LDAP
    When пользователь вводит неверный пароль 5 раз подряд
    Then аккаунт блокируется на 30 минут
    And пользователь видит сообщение: "Аккаунт временно заблокирован.
        Попробуйте через 30 минут или обратитесь к администратору"
    And администратору системы отправляется уведомление о блокировке

  Scenario: Сброс пароля по email
    Given пользователь "john.doe@company.com" зарегистрирован
    When пользователь запрашивает сброс пароля
    Then на email приходит письмо со ссылкой сброса в течение 60 секунд
    And ссылка действительна 24 часа
    And ссылка является одноразовой
```

## Проверка по примеру

- Сценарии показывают различные предпосылки и наблюдаемые результаты для входа, блокировки и сброса пароля. Привяжи каждый сценарий к истории, чью цель он проверяет.
- При переносе структуры проверь, какие пороги и сроки заданы проектом и от какого события их измерять. При проверке блокировки уточни исход непосредственно перед порогом и при достижении порога, когда это нужно для приёмки.
- Переносы строк внутри шагов сохранены из справочника. Для исполняемого файла .feature запиши каждый шаг на одной строке.
