# Уточнение требований для проверки

Пример из `wiegers_sa_reference.md`, § 1.4, таблица плохих и хороших требований (строки 158–164).

| ❌ Плохое требование | ✅ Хорошее требование |
|---------------------|----------------------|
| Система должна быть быстрой | Время ответа на запрос списка устройств не должно превышать 500 мс при p95, нагрузка 100 RPS |
| Система должна поддерживать большое количество устройств | Система должна управлять не менее чем 10 000 сетевых устройств одновременно |
| Интерфейс должен быть удобным | Пользователь должен иметь возможность найти алерт по ID устройства за не более чем 3 клика |
| Данные должны быть защищены | Все соединения должны использовать TLS 1.2+; пароли хранятся в виде bcrypt-хэша (cost factor ≥ 12) |
| Система должна уведомлять пользователей | Система должна отправлять SMS-уведомление дежурному инженеру в течение 60 секунд после генерации алерта уровня CRITICAL |

## Проверка по примеру

- Сопоставь слово «быстро» с явной метрикой, перцентилем и нагрузкой, а «уведомлять» с получателем, событием, каналом и сроком.
- Пример про защиту объединяет требования к соединению и хранению паролей. Проверь оба условия по отдельности, если они применимы.
- Запрашивай недостающие значения у пользователя. Эти пары показывают точность записи, а значения относятся к контексту примеров.
