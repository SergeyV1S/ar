# Нарушения INVEST

Пример из `wiegers_sa_reference.md`, § 5.2, таблица типичных нарушений (строки 522–527).

| Нарушение | Пример плохой Story | Как исправить |
|-----------|--------------------:|---------------|
| Не независимая | «Как пользователь, я хочу зарегистрироваться И авторизоваться» | Разбить на две Story |
| Не ценная | «Как разработчик, я хочу рефакторинг БД» | Выразить через бизнес-ценность |
| Не тестируемая | «Как пользователь, хочу удобный интерфейс» | Добавить конкретные AC |
| Слишком большая (Epic) | «Как инженер, хочу полный модуль алертов» | Разбить на User Stories |

## Проверка по примеру

- Найди независимые пользовательские цели внутри истории. Пример регистрации и входа показывает, куда провести границу.
- Для «удобного интерфейса» запроси измеримые или наблюдаемые условия, а для технической задачи выясни пользовательскую ценность.
- Раздели эпик на меньшие истории с результатом для пользователя или стейкхолдера и оцени их отдельно.
