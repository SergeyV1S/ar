# Спецификация Use Case

Основание в `wiegers_sa_reference.md` — § 7.1, § 13 (вариант использования).

Описывай взаимодействие актора с системой ради законченной цели. Название формулируй глаголом и существительным, например «Подтвердить алерт». Наименование API сохраняй как техническую ссылку, если оно есть во входных требованиях.

| Поле | Содержание |
|---|---|
| ID, название, версия, автор, дата, статус | ID и название обеспечивают навигацию. Остальные поля заполняй при наличии данных. Статус согласования бери из подтверждённого источника |
| Краткое описание | Цель основного актора, результат и ценность |
| Акторы | Основная роль достигает цели. Вторичные роли или внешние системы участвуют во взаимодействии |
| Предусловия | Что должно быть истинно до начала взаимодействия |
| Постусловия успеха | Что изменилось и что стало доступно после успеха |
| Основной поток | Последовательность действий актора и наблюдаемых реакций системы на успешном пути |
| Альтернативные потоки | Условия отклонения, шаги, возврат к основному пути или завершение |
| Исключения | Ошибки и недоступные операции, реакция системы и результат |
| Требования к производительности | Применимые подтверждённые ограничения со ссылкой на шаг или исход |
| Бизнес-правила | Правила, определяющие допустимость и результат действий |
| Open Issues | Вопросы о поведении и зависимостях, требующие решения |
| Связи | Связанные UC, FR, US и при наличии исходные BR/UR, критерии и тесты |

Если задано событие запуска, укажи его в кратком описании или первом шаге. Для ветвей, правил и отношений используй профильные справки из SKILL.md.
