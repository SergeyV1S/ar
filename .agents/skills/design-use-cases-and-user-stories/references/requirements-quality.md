# Качество требований

Основание в `wiegers_sa_reference.md` — §§ 1.4, 12.1 и 14.2 (антипаттерны документации).

| Критерий | Вопрос перед выдачей результата |
|---|---|
| Полнота | Описаны ли применимые условия, ветви и исходы |
| Однозначность | Понимаются ли одинаково роли, статусы, временные рамки, границы и результаты |
| Тестируемость | Есть ли наблюдаемое или измеримое ожидание и необходимые условия проверки |
| Реализуемость | Позволяют ли известные границы и ограничения выполнить требование |
| Трассируемость | Можно ли найти источник требования, связанную ветвь и проверку |
| Атомарность | Выражает ли отдельная формулировка одно самостоятельное поведение |
| Непротиворечивость | Совпадают ли правила во всех относящихся к ним материалах и артефактах |
| Актуальность | Относится ли требование к текущему объёму и действующей версии проекта |

Для быстрой проверки используй формулировку SMART из справочника. Она объединяет конкретность, измеримость, достижимость, релевантность и прослеживаемость. Затем проверь остальные критерии из таблицы.

Ищи расплывчатые слова, скрытые допущения, склеенные требования, новые функции без основания и технические решения, случайно принятые за пользовательские потребности. Нарушение, которое требует решения о логике, превращай в конкретный вопрос. Факты, предположения и согласованные решения должны быть различимы в результате.
